# Identidad visual — V1.0

## 1. Nombre provisional

Propongo trabajar inicialmente con:

# PisoClaro

La idea del nombre es transmitir:

- reglas claras;
- organización;
- transparencia;
- convivencia;
- control sin parecer una aplicación punitiva.

También encaja con todos los módulos: normas, tareas, compras y dinero.

Otras alternativas que podemos valorar más adelante:

| Nombre | Enfoque |
|---|---|
| PisoClaro | Transparencia y convivencia |
| Convivio | Más moderno y general |
| Pacta | Centrado en acuerdos |
| MiPiso | Muy directo |
| PisoSync | Más tecnológico |
| Convive | Simple y amigable |

Para continuar el diseño usaré **PisoClaro** como nombre provisional.

---

# 2. Personalidad visual

La aplicación deberá transmitir:

**Orden + claridad + confianza + neutralidad**

No deberá parecer:

- una app policial;
- una aplicación de castigos;
- una aplicación infantil;
- una herramienta empresarial demasiado fría.

El estilo será moderno y limpio, parecido a aplicaciones actuales de productividad.

---

# 3. Color principal

Color principal recomendado:

**Azul índigo**

Referencia:

`#4F46E5`

Se utilizará en:

- botones principales;
- navegación activa;
- elementos seleccionados;
- acciones principales;
- logotipo.

Motivo:

El azul transmite confianza y organización, mientras que el tono índigo aporta un aspecto moderno.

# 15. Tarjeta “Hoy”

Será el elemento dominante de Inicio.

Deberá mostrar exclusivamente cosas relevantes para las próximas horas.

Ejemplos:

**20:00 · Ducha**

**Hoy · Tirar basura**

**Antes de las 21:00 · Limpiar baño**

No aparecerán tareas futuras innecesarias.

---

# 16. Añadir falta

**⚠ Añadir falta**

rojo.

Esto la diferenciará de una acción destructiva real.

# 27. Animaciones

Serán discretas.

Ejemplos:

Al completar una tarea:

**check + pequeña animación**

Al registrar una falta:

**confirmación suave**

Al pagar una deuda:

**actualización animada del balance**

Duración aproximada:

**150–250 ms**

No utilizaremos animaciones decorativas largas.

---

# 28. Feedback táctil

En Android podremos utilizar vibración/haptic feedback ligero en acciones importantes:

- completar tarea;
- registrar;
- aprobar;
- confirmar pago.

Nunca será obligatorio.

---

**48 × 48 dp**

No se dependerá únicamente del color para representar estados.

No solo:

🟢

sino:

**✓ Aprobada**

---

# 30. Diseño responsive

Aunque inicialmente sea Android, la interfaz se diseñará para funcionar correctamente en diferentes tamaños de pantalla.

Se utilizará principalmente:

**scroll vertical**

y se evitarán anchos fijos.

---

# 31. Principios UX

Antes de añadir cualquier elemento visual aplicaremos estas reglas:

**¿El usuario necesita verlo ahora?**

Si no → se oculta en una pantalla secundaria.

**¿Puede hacerse con menos pasos?**

Si sí → se simplifica.

**¿Una persona entiende qué ocurrirá al pulsarlo?**

Si no → se cambia el texto.

---

# 32. Estilo final

PisoClaro tendrá un aspecto:

**Minimalista**

pero no vacío.

**Moderno**

pero no futurista.

**Serio**

pero no empresarial.

**Amigable**

pero no infantil.

Visualmente estará más cerca de una aplicación moderna de productividad y finanzas personales que de una aplicación de control o vigilancia.
